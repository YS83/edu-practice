# 연속 검색에서 늦게 온 이전 응답이 새 결과를 덮어씀

`components/candidates/tracker.tsx`의 단지 등록에서 실거래가 조회(`lookup`)와 단지 위치 조회(`loadPlaces`)가 응답이 최신 검색의 것인지 확인하지 않고 상태에 넣는다.

- 증상: 사용자가 단지명을 바꿔 연속으로 검색하면, 먼저 보낸 요청의 응답이 나중에 도착해 새 결과 목록 옆에 이전 검색의 지도(또는 결과)가 표시될 수 있다.
- 근거: `code-review low` 지적. 재현은 하지 않았다. 응답이 늦는 상황(카카오 지연이나 느린 망)에서 연속으로 검색해야 생긴다.
- 다음 단계: 검색을 시작할 때마다 증가하는 번호를 두고, 응답이 왔을 때 번호가 최신일 때만 상태에 반영한다(또는 AbortController로 이전 요청을 취소한다).
